# গৃহশিক্ষক/শিক্ষিকা দিচ্ছি — Website

একটা টিউটর-ম্যাচিং ওয়েবসাইট: অভিভাবক টিউটর খোঁজার ফর্ম পূরণ করেন, টিচার রেজিস্ট্রেশন করেন, আর ব্যাকএন্ড (Google Apps Script + Google Sheets) স্বয়ংক্রিয়ভাবে দুই পক্ষকে ম্যাচ করে দেয়।

## ফাইল তালিকা

| ফাইল | কাজ |
|---|---|
| `index.html` | দুটো ফর্ম — অভিভাবক (Guardian) ও টিচার — একই পেজে ট্যাব আকারে |
| `style.css` | ভিজ্যুয়াল ডিজাইন — গার্ডিয়ান সাইডে গভীর সবুজ, টিচার সাইডে কালো |
| `script.js` | সব ফ্রন্টএন্ড লজিক — ফর্ম উইজার্ড, কাসকেডিং ড্রপডাউন, সাবমিশন |
| `areas-data.js` | জেলাভিত্তিক canonical এরিয়া-লিস্ট + spelling-variant search index |
| `subjects-data.js` | মিডিয়াম → ক্লাস-গ্রুপ → বিষয় কাসকেডিং ডেটা |
| `apps-script.gs` | ব্যাকএন্ড — Google Apps Script-এ পেস্ট করার জন্য |

## ডিজাইন

- ব্র্যান্ড কালার: **গার্ডিয়ান সাইড = গভীর সবুজ**, **টিচার সাইড = কালো** (লোগোর দুই রঙ)
- ফন্ট: হেডিং-এ "Baloo Da 2", বডি টেক্সটে "Hind Siliguri"
- হেডারে খাতার মার্জিন-লাইন motif
- Top-এ দুটো ট্যাব: **টিউটর খুঁজছি (অভিভাবক)** vs **আমি পড়াতে চাই (টিচার)**

## অভিভাবক (Guardian) ফ্লো

৩-ধাপের উইজার্ড, প্রতি ধাপে progress indicator সহ:

1. **যোগাযোগ** — জেলা → এরিয়া (canonical লিস্ট থেকে single-select, searchable dropdown, ভুল বানানেও autocomplete মিলে যায় variant-index দিয়ে), বিস্তারিত ঠিকানা (ঐচ্ছিক, রেফারেন্সের জন্য — ম্যাচিং-এ ব্যবহার হয় না), ফোন
2. **শিক্ষার্থীর তথ্য** — প্রতি শিক্ষার্থীর জন্য মিডিয়াম → ক্লাস → বিষয় (চিপ, "সকল বিষয়" টিক দিলে বাকি সব নিষ্ক্রিয় হয়ে যায়) — cascading, `subjects-data.js` থেকে
3. **সময়সূচী ও বাজেট** — দিন, সময়, বেতন, বিশেষ শর্ত

সাবমিট করলে ব্যাকএন্ড স্বয়ংক্রিয়ভাবে:
- একটা রেডি-টু-পোস্ট টেক্সট বানায় (WhatsApp/FB পোস্টের জন্য)
- সম্ভাব্য টিচারদের সাথে ম্যাচ করে (নিচে দেখুন) এবং টপ ১০ জনের নাম+ফোন+স্কোর সরাসরি শিটে লিখে রাখে

## টিচার রেজিস্ট্রেশন ফ্লো

সাইটের ভিতরেই নেটিভ মাল্টি-স্টেপ ফর্ম (আগে external Google Form ছিল):

- ব্যক্তিগত তথ্য, যে জেলায় পড়াতে চান (Target_District) → সেই জেলার canonical এরিয়া-লিস্ট থেকে **multi-select চিপ পিকার** (তালিকায় না থাকলে "অন্যান্য" ফিল্ডে লেখা যায়, শুধু রেফারেন্সের জন্য)
- বর্তমান ঠিকানা (রেফারেন্স, ম্যাচিং-এ ব্যবহার হয় না)
- শিক্ষাগত যোগ্যতা: বিভাগ, সেশন, প্রতিষ্ঠান, ডিগ্রী, এসএসসি/এইচএসসি তথ্য
- পড়ানোর তথ্য: সময়, শ্রেণি, মিডিয়াম, গ্রুপ, বিষয়, অভিজ্ঞতা
- NID/জন্মনিবন্ধন + দ্বিতীয় ID কার্ডের ছবি আপলোড — সরাসরি Google Drive-এ সেভ হয়, লিংক Sheet-এ যায়

সব তথ্য **Teachers** শিটে জমা হয় `Status = 'Pending'` দিয়ে — ম্যানুয়ালি রিভিউ করে `'Active'` করলে তবেই সেই টিচার ম্যাচিং-এ আসবে।

## ম্যাচিং সিস্টেম (`matchTeachers()`)

**ধাপ ১ — হার্ড ফিল্টার** (এই ৩টা ১০০% না মিললে candidate pool-এই আসবে না):
- `Target_District` — exact
- `Teachable_Classes` — গার্ডিয়ানের চাওয়া সব ক্লাস কভার করতে হবে
- `Teachable_Mediums` — গার্ডিয়ানের চাওয়া সব মিডিয়াম কভার করতে হবে
- (`Status` অবশ্যই `'Active'` হতে হবে)

**ধাপ ২ — বাকিদের ১০০ পয়েন্টের স্কোরিং দিয়ে র‍্যাংক:**

| ক্রাইটেরিয়া | পয়েন্ট | কীভাবে হিসাব হয় |
|---|---|---|
| এরিয়া এক্স্যাক্ট-মিল | ৩৫ | গার্ডিয়ানের canonical `Area` টিচারের canonical `Areas` লিস্টে হুবহু (trim করে) থাকলে ৩৫, নাহলে ০ — কোনো বানান-নির্ভরতা নেই, ১০০% নির্ভুল |
| জেন্ডার | ১৫ | গার্ডিয়ানের পছন্দ না থাকলে/"যেকোনো" হলে পুরো ১৫; পছন্দ থাকলে মিললে ১৫ নাহলে ০ |
| পছন্দের ডিগ্রী | ১৫ | গার্ডিয়ান নির্দিষ্ট না করলে পুরো ১৫; করলে মিললে ১৫ নাহলে ০ |
| পছন্দের প্রতিষ্ঠান | ১০ | একই যুক্তি |
| গ্রুপ/বিষয়-উপযুক্ততা | ১৫ | ক্লাস ৯+ এ কমার্স/সায়েন্স-স্পেসিফিক বিষয় হলে টিচারের ডিগ্রী (বিবিএ/এমবিএ বা বিএসসি/এমএসসি) মিলতে হবে; সাধারণ বিষয় বা নিচু ক্লাসে সবসময় পুরো ১৫ |
| অভিজ্ঞতা | সর্বোচ্চ ১০ | প্রতি বছরে ১ পয়েন্ট, ১০ বছরে ক্যাপ |

**ধাপ ৩** — স্কোর অনুযায়ী সাজিয়ে **টপ ১০ জন** রিটার্ন হয় (কোনো ন্যূনতম স্কোর কাটঅফ নেই — pool-এ যা আছে তা থেকেই)। প্রতিটা নামের পাশে বন্ধনীতে স্কোর % সহ শিটে লেখা হয়: `নাম - ফোন (৮৫%)`।

> পুরনো ঠিকানা/Locations কীওয়ার্ড-মিল ভিত্তিক ম্যাচিং ফাংশন (`extractKeywords`/`keywordOverlap`) ফাইলে রাখা আছে ব্যাকআপ/রেফারেন্সের জন্য, কিন্তু আর স্কোরিং-এ ব্যবহৃত হয় না।

## শিটে ম্যানুয়াল এন্ট্রি/এডিট সাপোর্ট

ফোনে শুনে সরাসরি Guardians শিটে এন্ট্রি টাইপ করলে বা কোনো কারেকশন করলেও পোস্ট+ম্যাচিং ফাংশন কাজ করে:

- **অটো-রিফ্রেশ:** Guardians শিটে যেকোনো ম্যানুয়াল এডিট করলে (`onEdit` ট্রিগার) সেই সারির Ready_Post ও Matched_Teachers/Matched_Count নিজে থেকেই রিফ্রেশ হয়ে যায়
- **মেনু:** শিটের উপরে "🔄 রিফ্রেশ টুলস" মেনু থেকে ম্যানুয়ালিও রিফ্রেশ করা যায় —
  - "এই সারির পোস্ট + ম্যাচিং রিফ্রেশ করো" (কার্সার যে সারিতে আছে)
  - "সব গার্ডিয়ানের ম্যাচিং রিফ্রেশ করো" — নতুন টিচার যোগ/এডিট করার পর পুরনো সব গার্ডিয়ানের ম্যাচিং একসাথে আপডেট করতে

## Setup (আপনার করণীয়)

### ১. Apps Script backend বসান
1. Google Sheet খুলুন → Extensions → Apps Script
2. পুরনো কোড মুছে `apps-script.gs`-এর সম্পূর্ণ কোড পেস্ট করুন
3. Deploy → Manage deployments → পুরনো deployment এডিট করুন (নতুন deployment করলে `script.js`-এ URL আপডেট করতে হবে)
4. **Execute as:** Me, **Who has access:** Anyone
5. Deploy করার সময় Google আপনাকে Drive access অনুমতি চাইবে (ফাইল সেভের জন্য) এবং Sheet-এর ভিতর থেকে ম্যানুয়ালি কিছু এডিট করলে বা "🔄 রিফ্রেশ টুলস" মেনু প্রথমবার ব্যবহার করলেও আলাদা করে অনুমতি (authorization) চাইবে — দুটোই approve করে দিন
6. প্রথমবার deploy/test করার সময় Sheet-এ automatically দুটো ট্যাব তৈরি হবে: **Guardians** ও **Teachers**

### ২. URL গুলো আপডেট করুন
- `index.html`-এ `your-domain-or-username.github.io/repo-name/` — আসল GitHub Pages URL বসান
- `script.js`-এ `scriptURL` — নতুন deployment URL হলে বদলান (পুরনো URL এডিট করলে বদলাতে হবে না)

### ৩. এরিয়া/সাবজেক্ট ডেটা আপডেট
নতুন জেলা বা এরিয়া যোগ করতে চাইলে শুধু `areas-data.js`-এ এক লাইন যোগ করলেই হবে — কোনো ফর্ম-লজিক বদলাতে হবে না।
